# 창 전환 기능 검증

## 적용 범위

설정의 **일반 → 창 동작**에서 자동 숨김과 Alt+Tab 제외 기능을 각각 제어합니다. 두 옵션의 기본값은 ON이며, 기존 YAML에 항목이 없어도 동일한 기본값을 적용합니다.

자동 숨김은 번역이 켜져 있고 연결된 게임 창이 존재할 때만 동작합니다. 게임과 번역기 이외의 앱이 전경에 있으면 메인 창을 최소화하고 번역창은 `Hide()`로 완전히 숨깁니다. 따라서 번역창의 최소화된 제목 표시줄이 바탕화면에 남지 않습니다. 번역기 입력란이나 설정 대화상자를 사용하는 동안에는 창을 유지합니다. 사용자가 지정한 번역창 표시 여부와 자동 숨김 상태는 별도로 관리합니다. 자동으로 숨겨진 동안 사용자가 창 표시를 끄거나 NPC 대사를 채팅창에 합쳐도 해당 창을 다시 표시하지 않습니다. 창 상태를 복원할 때는 입력 초점을 변경하지 않습니다.

Alt+Tab 제외 옵션은 채팅창과 NPC 대사창에 `WS_EX_TOOLWINDOW`를 적용하고 `WS_EX_APPWINDOW`를 해제합니다. 두 번역창은 작업 표시줄에서도 제외됩니다. 메인 창의 스타일은 변경하지 않습니다. 옵션 변경은 표시 중이거나 최소화되거나 숨겨진 번역창에 바로 적용됩니다.

## 자동 검증

일반 단위 테스트는 게임이나 화면 조작 없이 설정 기본값, YAML 호환성, 설정 메시지 전달, 초점 판정과 자동 복원 상태를 확인합니다.

```powershell
dotnet build src\IronworksTranslator\IronworksTranslator.sln -c Debug
dotnet test tests\IronworksTranslator.Tests\IronworksTranslator.Tests.csproj -c Debug
```

다음 테스트는 실제 Windows 창을 잠깐 생성하므로 대화형 데스크톱에서 별도로 실행합니다. 기본 테스트 실행에서는 건너뜁니다. 일반 창과 최대화된 창의 복원 상태, 전경 창과 스레드 활성 창의 유지, 투명한 최상위 번역창의 스타일 변경, 숨겨진 창의 상태 보존을 확인합니다. FFXIV와 번역 API는 사용하지 않습니다.

```powershell
$env:IRONWORKS_WINDOW_SMOKE = '1'
try {
    dotnet test tests\IronworksTranslator.Tests\IronworksTranslator.Tests.csproj -c Debug --filter FullyQualifiedName~WindowBehaviorDesktopTests
} finally {
    Remove-Item Env:\IRONWORKS_WINDOW_SMOKE
}
```

## 실제 게임에서 확인할 항목

자동 테스트는 실제 FFXIV의 화면 모드와 Windows 전환 목록 표시까지 검증하지 않습니다. 다음 항목은 앱을 실행해서 확인해야 합니다.

1. 번역을 켜고 FFXIV에 초점을 맞춥니다. 채팅창과 활성화한 NPC 대사창이 유지되는지 확인합니다.
2. Alt+Tab 목록에 IronworksTranslator 메인 앱만 표시되는지 확인합니다. 다른 앱으로 전환하면 메인 앱은 최소화되고 두 번역창은 완전히 숨겨지는지 확인합니다. 화면 아래쪽에 작은 번역창이 남아 있으면 안 됩니다.
3. 게임으로 돌아온 뒤 창이 이전 상태로 복원되고, 게임에 키보드 입력이 전달되는지 확인합니다. 메인 앱을 최대화한 상태에서도 반복합니다.
4. 게임을 직접 최소화한 뒤 같은 동작을 확인합니다. 메인 앱을 선택해서 설정이나 직접 번역 입력란을 사용하는 동안에는 창이 다시 최소화되지 않는지 확인합니다.
5. 메인 창을 직접 최소화하거나 NPC 창을 숨긴 상태에서 화면 전환을 반복합니다. 사용자가 지정한 상태가 유지되는지 확인합니다. NPC 대사를 채팅창에 표시하는 옵션도 함께 확인합니다.
6. 자동 숨김 옵션을 끄거나 번역을 끄거나 게임을 종료합니다. 자동으로 숨긴 창이 다시 표시되고 이후 화면 전환에 반응하지 않는지 확인합니다.
7. Alt+Tab 제외 옵션을 끄고 켭니다. 두 번역창의 Alt+Tab 및 작업 표시줄 표시가 바뀌며, 창 위치·크기·투명도·표시 상태가 유지되는지 확인합니다. 앱을 다시 시작한 후에도 두 설정값이 유지되는지 확인합니다.
8. 사용하는 게임 화면 모드와 다중 모니터 환경에서 1~7번을 반복합니다.

### 번역창을 완전히 숨기도록 변경한 후

- 번역창을 최소화할 때 바탕화면 아래에 작은 제목 표시줄이 남는 문제를 해결하기 위해, 번역창에는 최소화 대신 숨김을 적용했습니다. 메인 앱은 작업 표시줄에서 선택할 수 있도록 최소화합니다.
- Debug 솔루션 빌드는 경고 0개, 오류 0개로 완료했습니다. 기본 테스트 210개와 별도로 실행한 데스크톱 테스트 3개가 통과했습니다.
- 추가된 데스크톱 테스트에서는 숨겨진 번역창의 실제 HWND가 표시되지 않고 최소화 상태도 아닌지 확인했습니다. 자동 숨김 해제 후 위치와 입력 초점이 유지되고, 자동으로 숨겨진 동안 사용자가 지정한 표시 여부가 보존되는지도 확인했습니다.
- 실제 FFXIV 화면에서 변경 후 동작은 아직 재확인하지 않았습니다.

### 설정 화면의 높이와 휠 스크롤 변경 후

- 창 동작 옵션 아래의 부가 설명을 제거했습니다. 메인 앱의 기본 높이는 550에서 1100으로, 최대 높이는 800에서 1600으로 변경했습니다.
- 설정 화면의 모든 탭에서 내부 컨트롤 위로 휠을 움직여도 해당 탭을 스크롤합니다. 닫힌 선택 상자와 슬라이더의 값은 휠로 변경하지 않으며, 펼친 선택 목록은 기존처럼 목록 안에서 스크롤합니다.
- Debug 솔루션 빌드는 경고 0개, 오류 0개로 완료했습니다. 실제 Windows 창 테스트 4개를 포함한 전체 테스트 214개가 통과했습니다. 추가된 휠 테스트에서는 버튼, 선택 상자, 텍스트 입력란, 슬라이더와 그리드 위에서 페이지가 스크롤되는지 확인했습니다.

### 실제 Card와 NavigationView에서 스크롤 대상을 수정한 후

- 이전 휠 테스트에는 실제 `ui:Card`와 앱의 `NavigationView` 구성이 포함되지 않았습니다. 두 컨트롤과 실제 리소스 템플릿을 사용하는 재현 테스트를 추가하자, Card 위의 휠 입력이 스크롤되지 않는 문제가 확인되었습니다. 재현 당시 안쪽 스크롤 범위는 0이고 바깥쪽 범위는 1175였습니다.
- 안쪽 영역에 스크롤 범위가 없으면 상위 요소 중 실제 스크롤 범위가 있는 영역으로 휠 이벤트를 전달하도록 수정했습니다. 수정 전 실패한 재현 테스트가 수정 후 통과했습니다. Card의 배경 Border, Card 자체, 내부 버튼과 선택 상자 위에서 아래로 스크롤하고, Card 배경 위에서 위로 스크롤하는 동작을 확인했습니다.
- Debug 솔루션 빌드는 경고 0개, 오류 0개로 완료했습니다. 실제 Windows 창 테스트 5개를 포함한 전체 테스트 215개가 통과했습니다.
