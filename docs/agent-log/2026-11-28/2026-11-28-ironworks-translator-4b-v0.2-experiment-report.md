## 2. 결정적 실험 발견: `v0.2-r1` vs `v0.2-r2` (Interpretation)

### 2-1. `v0.2-r1` 실패 진단 (FFXIV 영문판 의역·재창작 드리프트)
- `v0.2-r1`은 `ffxiv-datamining`의 공식 `EN/DE/FR/JA → KO` 퀘스트 대사를 그대로 Axis 4(9,600건)에 투입했다.
- 정량 지표는 안정성 `0/151`이었으나, 실제 출력을 정성 검수한 결과 `a85`/`a100`에서 `"Are you ready for what lies ahead?" → "그럼, 출발해용!"` 같은 **의미 이탈(의역 환각)**이 발생했다.
- 원인은 **FFXIV 영어판이 일본어 원문을 대폭 재창작(transcreation)**하는 반면 **한국어판은 일본어 원문을 1:1 충실 번역**하기 때문이었다(`EN ↔ KO` 랜덤 5건 중 다수가 의미 불일치, `JA ↔ KO`는 5/5 1:1 일치).

### 2-2. `v0.2-r2` 해결책 (12B 1:1 역번역 출발어 + 100% 공식 한국어 타깃)
- **정답(한국어)**: `ffxiv-datamining`의 공식 한국어 대사 100% 그대로 유지 (합성 한국어 0%).
- **출발어(`EN/DE/FR`)**: 로컬 `MiLMMT-46-12B-v1.0.Q4_K_M.gguf`로 공식 한국어 대사를 `KO → EN/DE/FR` 1:1 역번역 (`8,472 / 8,603` 통과, 통과율 98.5%). `JA → KO`는 원래 1:1 정합성이 높아 공식 원문 쌍을 유지.
- **효과**:
  - `eval_loss`: `1.658` (`r1`) → **`1.173`** (`r2`, **-0.485 개선**)
  - `a100` 스타일 제어율: `45/80 (56.3%)` → **`61/80 (76.3%)`**, 의역 환각 완전 해소, `distractor` 오삽입 `1/25 → 0/25`
  - **`alpha=0.92`** 선형 병합으로 `a100`에서 보였던 일반 번역 2건의 미세 어감 차(`お先に失礼します`, `KO→EN` 단축)까지 모두 원복하면서 `Q4_K_M` **58/80**, `Q8_0` **64/80 (80.0%)** 달성.

## 3. 런타임 NPC 말투 DB 및 앱 통합 설계

1. **런타임 용어집 `2026-11-27.4` (`npc_styles`)**:
   - `tools/milmmt-glossary-builder/korean_style.py`: 8화계 종결어미 분류기 및 대표 화계 추론.
   - `tools/milmmt-glossary-builder/npc_style_overrides.json`: 주요 MSQ/새벽/확장팩 NPC 46명 공식 어투 검증 오버라이드.
   - 고유명사 NPC(`ENpcResident` `Article == 1` + 대문자 시작)만 자동 추출해 일반 역할명(`guard`, `merchant`) 오지정을 차단 → 총 **7,089건**(`EN 1,740`, `DE 1,758`, `FR 1,756`, `JA 1,799`).
2. **앱 적용 범위 (`IronworksTranslator`)**:
   - `MiLMMTModelProfile.SupportsStylePrompt` 게이트 도입 (`v0.1` 및 기본 `MiLMMT`는 `false`, `v0.2`만 `true`).
   - `MiLMMTTranslator.ShouldApplyNpcStyle`: `Dialogue` 요청이면서 **`EN / DE / FR → KO`**일 때만 `Style:` 주입 (`JA → KO`는 일본어 원문 자체의 어투 뉘앙스를 보존).
   - `TranslationCacheKey`에 `StyleHint`를 포함해 동일 대사라도 화자별 어투 캐시 충돌 방지.
   - `DialogueWindow` 및 `ChatWindowViewModel` 양쪽 NPC 대사 번역 경로에 원문 `speakerName` 전달.
